## 你改到以上文件了吗？

### 如果你没动这些文件

直接 pull，不会有冲突：

```bash
git pull --rebase origin develop
```

### 如果你也改了以上某个文件

先检查冲突范围：

```bash
git fetch origin develop
git diff HEAD..origin/develop -- <你改过的文件路径>
```

然后：

```bash
git pull --rebase origin develop
```

冲突时**以下几个函数/逻辑必须保留**（删除会导致云图永远黑屏）：

| 文件 | 必须保留的内容 |
|---|---|
| `story.js` | `_saveProgressToCache(nodeId)` 函数定义，`_saveCurrentStory()` 函数定义，以及 `prevStory()` / `nextStory()` 中 `this._saveCurrentStory()` 调用，`goBack()` 和 `markStoryComplete()` 中 `this._saveProgressToCache(nodeId)` 调用 |
| `exhibit.js` | `saveProgressCache()` 中的合并逻辑（`existingTl.indexOf(...)` + `existingTl.push(...)`），不能直接用 `unlockedClouds` 覆盖写入 |
| `cloudUtil.js` | `getCloudNodes` 和 `resetProgress` 的导出 |

### 安全做法（推荐）

如果你本地有未提交的改动：

```bash
git stash                    # 暂存本地改动
git pull --rebase origin develop  # 拉取最新
git stash pop                 # 恢复本地改动
# 如有冲突，逐个文件解决后 git add
```

## 验证方法

在微信开发者工具中操作：进入故事页 → 浏览几个故事 → 返回 → 打开云图页面。

控制台应看到：
```
[story] 直接写缓存, nodeId: n1 当前已解锁: ["n1"]
[story] 直接写缓存, nodeId: n2 当前已解锁: ["n1","n2"]
[cloud] 读取缓存 timelineNodes: ["n1","n2"]
[cloud] 节点点亮: 序章开启 ( node_1 )
[cloud] 连线点亮: 人生起点
```

如果云图仍然全暗且控制台无 `[cloud] 读取缓存 timelineNodes` 日志 → 缓存写入链路断了，检查上述「必须保留」的代码是否在合并时丢失。
